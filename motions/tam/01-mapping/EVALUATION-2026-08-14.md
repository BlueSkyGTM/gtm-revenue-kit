(operator-proven); the qualitative cost split above is the honest pre-operation
contract."* Same reasoning keeps the header cost qualitative — correctly so.

### One new flag — the estate suppression pass versus principle 5's letter. **Ratify or remove; Ray rules.**

`revenue-growth/CONTEXT.md` rule 2 adds a third suppression pass: *"no company in the
albatross `revenue-engineering` account's live audience is contacted from this one, in
either direction, by name and domain only."*

The purpose is real and the scoping is careful — one operator's two businesses writing
to the same company in the same week is a genuine failure, and the rule reads names and
domains only, never books or context. But it contradicts the **letter** of the recorded
law in two places: principle 2 ("accounts never read each other") and principle 5 /
old isolation §4 ("one account's list is never checked against another's campaign").
This is not consent-transfer — consent stays per-account — it is audience-collision
prevention, which the law as written never contemplated.

An unrecorded exception to a recorded law is how drift starts, however good the
exception. Two clean resolutions: **(a)** ratify it as a named exception — an
"estate-collision rule" written into `foundations/principles.md` §5 (or `estate.md`),
scoped exactly as implemented: same-operator deployments, name+domain only,
bidirectional, nothing else crosses; or **(b)** remove the pass. The second brain's read
is that (a) is right — the failure it prevents is real and tenet-adjacent — but the law
must say so out loud. Until ruled, the pass exists in one wing's contract and nowhere in
law, which is exactly the shape every prior drift incident took.
