# Rulings — the operator's decisions, kit-scoped

*Append-only. One line per ruling, dated, with its reversal condition where one exists.
Provenance: the operator's rulings, distilled to what binds core — facts about the
operator's businesses stay in the operator's own record. Operator-proven by definition:
these **are** the decisions.*

**What this file is.** The calibration workspace where rulings are made is volatile by
design — current status, history, business facts, most of which fail the swap test and
none of which should travel. **This file is the channel between the two: the residue of
each ruling that binds core, stripped of the facts that produced it.** It is appended to,
never replaced.

**How to use it.** A ruling here outranks an inference. If a draft assumes something this
file settles, the file wins. If a ruling contradicts something else in core, that is a
finding — surface it rather than blending.

**How a ruling gets here.** The operator rules; the ruling is stripped to what survives
the swap test; it lands as one line with a date. If the stripped version would name an
account, a deployment, or a person, it does not belong in core at all — it belongs in
that account's own record.

## Structure and discipline

**2026-08-11 — The laws are laws, not principles.** The eight functions describe what any
revenue system must do; a system failing one fails regardless of design choices.
Principles guide design and could be chosen otherwise. *Consequence:* the derivation check
is a real audit — what cannot name a law is a finding, not a thing to force.

**2026-08-11 — TAM is an artifact, not a layer of the framework.** Owned by the targeting
subsystem. Its apparent height was centrality mistaken for height. *Consequence:* the
staged motion that builds and consumes it is a different object; do not conflate them.

**2026-08-11 — Subsystems are named by the laws.** Each law is discharged by a named part
of the backbone; governance spans all eight. *Consequence:* backbone decomposition is
derived, not designed.

**2026-08-11 — Systems predate architecture.** Transcribe from operating history; never
author ahead of it. *Exception, permanent:* constraints, because their subject is what
must never happen. *Consequence:* folders wait for content; empty is visible, invented is
not.

**2026-08-11 — Models are held until they describe something that runs.** A model enters
the architecture layer by describing a system in operation. *Reversal per model:* named
adoption condition met.

**2026-08-13 — Every gate names its scope.** An approval rule read from one party's record
binds that party, never the operation and never core. *Origin:* the sixth
inference-as-fact instance.

**2026-08-13 — Frame invariant, filling swappable, declared per account.** No layer
hard-codes its implementation; every slot an account runs is declared explicitly, never
left implicit.

**2026-08-14 — Isolation admits no exception.** Accounts and deployments never read each
other, including audience-collision checks between deployments the same operator owns.
*Origin:* a cross-deployment suppression pass, proposed for a real failure, removed rather
than ratified. *Consequence:* a good reason is not a reason to hold an unrecorded exception
to a recorded law. *Challenged the same day (audit F3): the "different sender" premise is
thin for two businesses one person owns reaching overlapping networks, and the framing that
produced this ruling came from the construction session, not from the operator's own
reading. **Worth re-ruling on better framing.** Ledgers stay separate meanwhile.*

## Method and doctrine

**2026-08-13 — The four-dimension signal split is adopted** (fit / intent / relationship /
timing). *With:* the source's weights are reported, not verified — treat as starting
values at most. *Resolves:* whether relationship and timing are scored dimensions or play
triggers — **both**: dimension feeds the score, play handles the firing.

**2026-08-13 — Benchmarks stay out of core until the kit's own campaign data lands.**
Retired figures had no known source; accounts set their own. *Kept:* the diagnostic shapes
are mechanism and may stay. *Reversal:* first campaign results enter an account's scoring
model with provenance "operator-proven."

**2026-08-13 — The waste taxonomy is the admission rubric's sharp edge.** A method enters
core by naming which waste, at which seam, it prevents. What cannot name one is reference,
not law. *Challenged 2026-08-14 (audit F4): the test cannot fail — every method prevents
some waste — so it works for placement, not admission. Principle 1 is the test that can
fail. Awaiting the operator's amendment; recorded here rather than silently changed.*

**2026-08-13 — Revenue engineering subsumes this kit; the kit keeps its name.** "GTM"
correctly names the execution layer this machinery serves. No rename, no re-scope.

**2026-08-14 — The TAM improvement: the ignored gaps are part of the map.** The basic
system answers "who can I find that would buy and is worth enriching." The improvement
names the excluded on the same artifact — anti-ICP rules with reasons, the below-threshold
tier, suppression marked — as first-class output rather than byproduct. *Consequence:*
exclusions are debugged like scoring is.

**2026-08-14 — Stage evaluation gates stage construction.** Each landed stage is evaluated
before the next is built. *Origin:* the construction law applied to the kit's own
assembly. *Amended 2026-08-14 (below):* the evaluator changed; the gate did not.

## Runtime

**2026-08-13 — The kit's future is a runtime over a unified GTM API surface.** Basic tools
are reached through it; no channel is retired by the choice. *Standing rule:* no
scaffolding ahead of the operator's spec.

**2026-08-13 — The send wall translates; it does not retire.** "No wired sender in the
repo" was the file-era form of a permanent rule: **sends execute only through gates that
bind mechanically** — suppression checked before every batch, caps enforced, approval
scopes enforced per account. A runtime without mechanical gates is the wall demolished,
not upgraded.

## Authority

**2026-08-14 — Distilled doctrine is questioned, not inherited.** Material arriving as
foundations carries its source's status with it; a file is not authoritative because it
arrived shaped like doctrine. *Origin:* the eight functions were made rung 1 on a
self-published generalist source that no one audited, while the same pass rigorously
audited an instrument's evidence. *Consequence:* provenance markers on doctrine name the
source's standing, not just its name — and the audit record
(`decisions/2026-08-14-foundations-audit.md`) is the shape that check takes.

**2026-08-14 — The second brain is retired from the construction loop.** Evaluation,
research, and triage judgments move to the construction session; the operator remains the
final gate. *Consequence:* the stage-evaluation gate stands, self-run against
`failure-modes.md` §The self-check, with the result recorded beside the stage — a written
self-check is weaker than an independent evaluator, and recording it is what keeps the
weakness visible. *Reversal:* an independent evaluator returns to the loop.

**2026-08-14 — Between perfect synthesis and a working result, take the result.** These
foundations are checks to run, not a lens to narrate through; over-application is the
ceremony corruption they warn about. *Consequence:* a draft that reads as compliance
narration has failed the file it is citing.
